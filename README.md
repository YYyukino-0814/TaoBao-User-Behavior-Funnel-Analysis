> **一句话定位**：用 1000 万条淘宝真实用户行为记录，把"逛 → 加购 → 买"这条路每一步流失多少人、用户在什么时候最想买讲清楚，最后给出 3 条能落地的运营动作。

## 1. 这个项目为什么值得做（面试 30 秒版本）

电商数分面试绕不开"转化"。"为什么进来 100 个人只有 2 个下单"是业务天天在问的问题。
上一个 RFM 项目回答的是**"哪些用户值钱"**，这个项目回答更靠前的**"用户在哪一步流失、为什么会流失"**。

**但这个项目真正值钱的地方，不是查到了什么，而是三条"听起来很对、数据不支持"的常识被推翻了：**

| 常识 | 数据说的 |
|---|---|
| ① 把资源押给重度用户 | 重度用户拿走 **68% 的流量**，只产出 **53% 的成交**；单位行为购买产出 2.02（轻度）vs 0.78（重度） |
| ② 加购是转化扳机，催加购最有效 | 加购之后下一步成交概率 **0.88%**，**比随机挑一个非购买动作的平均 1.17% 还低** |
| ③ 晚上加购最多，是黄金时段 | 加购渗透率 22–23 点最高（31.21%），但**加购者购买率最低**（38.90%）；双高点在**上午 10 点** |

> ⚠️ **叙事在 S2 有过一次转向，这件事面试一定会被问，要讲得清。**
>
> **第一步：原问题问了，也答了。** "人丢在哪一步"——浏览→加购 67.17%、加购→购买 64.22%，**两步只差 2.95 个百分点，没有卡点**。
>
> **第二步：这个答案没法用。** 漏斗分析的唯一用途是回答"资源该往哪一步投"，两步掉得一样狠就没有答案。而且更根本的是——**不是"漏斗正常"，是"漏斗在这份数据上不成立"**：75% 的浏览→加购率在真实电商是个位数，原因和 58% 那个陷阱是同一件事，**这批用户本来就是想买的人，哪一步都不怎么漏**。
>
> **第三步：转向的触发点是一个具体的反常，不是"做不下去"。** 看加购用户去向时，三个数对不上：加购过的人 **71.87%** 最终买了东西，但只有 **31.13%** 买回了自己加购的那件，商品级更是只有 **6.47%**。**同一批人、同一段时间，从 71.87% 掉到 6.47%**——这个落差才是要查的。
>
> **第四步：新老问题是同一格的两层，不是换话题。** 原问题问的是**数量**（人有没有漏），新问题问的是**含义**（加购标记了什么）。漏斗只告诉你"人从浏览走到了加购"，没告诉你"走到加购意味着什么"。
>
> **标准框架套不上时，换问题比硬套结论更值钱。** 但要能说清"为什么换"——说不清，就会像"找不到卡点就换个说法"。

### 电梯陈述（可脱稿背）

> "我用 1000 万条淘宝行为日志做交易漏斗分析。第一个发现是**标准漏斗在这份数据上失效了**——浏览到加购 67.2%、加购到购买 64.2%，两步只差 3 个百分点，**没有卡点**。而且数据里 **58% 的用户有购买行为**，真实电商只有个位数，所以这批用户是筛过的活跃用户集，不能当全站流量看——**这个我发现后主动讲出来，因为被追问才承认就是减分。**
>
> 卡点找不到，我就把问题换掉了：不问'哪一步漏人'，问'**购物车到底意味着什么**'。查出来三件事：加购带来的成交**78% 发生在会话结束之后**；加购之后下一步的成交概率 **0.88%，比平均还低**；按商品算，加进购物车的 39 万件里只有 **6.21%** 被同一人买走。
>
> 所以结论是**购物车不是待付款清单，是意向标记**——'针对购物车商品在加购当下催单'这个常见动作方向是错的。
>
> 顺着这个做了召回测算：93.79% 的加购商品七天内没成交，涉及 66,542 人。但我先给自己立了条纪律——**这份数据没有金额字段，所以只用件数和人数，不给 GMV 也不给 ROI**，客单价哪来的一问就穿。测算结果是名单不该平均发：**一半的人握着 84% 的沉默件**；时点上**最大的一档是'6 到 24 小时'占 33%**，比'1 小时内'还大，所以该第二天上午推。
>
> **最后我明确说了那几档提升幅度是我拍的、不是数据算的**，要做 A/B 才能验证。这是结论，不是局限。"

和 RFM 的差异（写简历时的增量，得能一句话说清）：

| | RFM 项目（上一代） | 本项目（旗舰） |
|---|---|---|
| 数据 | 107 万行订单 | **1000 万行行为事件流**（量级 + 形态升级） |
| 分析对象 | 客户价值分层（谁值钱） | **转化链路 / 留存 / 复购 / 时间结构 / 行为序列** |
| 统计 | 订单表上的卡方 / KW | 同一套检验在真实事件流重跑 + **效应量与复现性检验** |
| 工具 | pandas 为主 | **SQL（DuckDB）为主**，实弹练四模板；Tableau 出看板 |

## 3. 分析主线（S1–S10）

| 步 | 干什么 | 一句话结论 | 状态 |
|---|---|---|---|
| S1 | 认识数据 + 四种行为占比 | 浏览约占九成，全站天然逛多买少 | ✅ |
| S2 | **交易漏斗主线** | 两步通过率几乎一样，**没有卡点**；购物车是比价清单 | ✅ |
| S3 | 时间规律（小时分布） | **加购的含金量 10 点 62.81% vs 23 点 39.29%**；查实 12-02 的异常 | ✅ |
| S4 | 日活留存 | 回访率几乎不衰减（D1 74.90% → D3 73.12%），因为用户本来就天天来 | ✅ |
| S5 | 复购分析 | 复购口径有构造重叠陷阱，拆开后结论完全不同 | ✅ |
| S6 | 类目转化差异 + 卡方 | 差 20.6 倍，但 **Cramér's V 只有 0.13**；依据是复现性不是 p 值 | ✅ |
| S7 | 轻/中/重度分层 | **重度用户 68% 流量只产 53% 成交**；"活跃"≠"买单" | ✅ |
| S8 | **行为路径 / 序列**（深水区） | 66.37% 的会话是纯浏览；**加购后成交 78% 在会话外** | ✅ |
| S9 | **加购召回测算**（深水区） | 93.79% 沉默；**一半的人握 84% 的机会**；最大档是 6~24 小时 | ✅ |
| S10 | 汇总 3 条动作 + 看板聚合表 | 见 `分析文档/10_结论与行动建议.md`（看板规格在内，**看板不搭**） | ✅ |

> **S8 / S9 是"深水区"，也是这个项目区别于网上大量同款淘宝分析的地方。** 别人普遍只做到 S7（占比、趋势、分布），深水区做的是"用户真实走的路径"和"能开给运营的动作 + 情景测算"——这两块才是面试里能出彩、也最容易被追问的地方。

**三条动作建议（S10 收口）**：

1. **加购召回的时点从"加购当下"推到"次日上午"** —— 名单发 D 层 32,942 人（握 84.47% 沉默件），站内可触达 89.21%（下界），每提升 1 个点 = 3,650 件，**必须 A/B 验证**
2. **KPI 按类目定，但依据是复现性**（Spearman 0.994 / Top10 10/10），**不是 p 值**（p 值在这里没有决策价值）
3. **别把"高活跃"当"高价值"** —— 逛型要短决策路径，买型要高频次回访，两类人策略方向相反

## 5. 埋好的几个"面试坑位"（做项目时就防）

- 被问 **"你这转化率/购买渗透率是不是太高了？"** → ⭐**主动讲**：7 天窗口下 **58.04% 的用户有购买行为**（9 天窗口是 68.05%），真实电商只有个位数——说明这份数据是筛选过的活跃/购买倾向用户集。所以我**只讲相对结构、不外推绝对水平**。主动点破是加分（数据敏感度），被追问才承认是减分。
- 被问 **"有 GMV 吗？"** → 答：数据集只有行为、无金额字段，所以用转化链路替代成交额拆解，回答"钱从哪一步漏的"；S9 的测算**只用件数和人数**，不给 GMV 也不给 ROI。
- 被问 **"样本怎么来的？"** → 答：全量 1 亿行，**按用户哈希抽 10%**，不是截前 N 行（文件按 user_id 聚块排，截行只会抽到最早注册的老用户）、也不是按行抽（会把稀有的购买事件抽没，导致转化率被低估）。抽完验证：行为占比与全量的偏差 <0.06 个百分点（详见 `00_口径与数据说明.md`）。
- 被问 **"为什么把 12-02/12-03 剔了？"** → ⭐**方向别答反**：那两天的**当日活跃覆盖率从 72~75% 跳到 98.19%**——同一个 10% 抽样，两天不可能差这么多。排除过限时活动（按小时比值全天平坦，1.30 倍）和拉新（当天 9.7 万活跃里只有 **2 个**新面孔）。完整判定见 `03_时间规律.md` 第 2 节。
- 被问 **"复购怎么定义的？"** → 答：无订单号，用"有购买行为的自然日数"近似，会保守低估——口径先行，把近似写清楚。
- 被问 **"加购到购买 64%，你这不是说购物车越满成交越高、就该催单吗？"** → ⭐**这是最容易被问倒的地方**：64.25% 是**人的口径**（加购过的人最终买了东西），但**商品口径**只有 6.21%（被加购的那件商品被同一人买走）。两个数都对，问的不是一回事。落差正是结论：**买东西的人多，买"购物车里那件"的人少。**
- 被问 **"6.21% 是不是因为数据只有 7 天？"** → 答：**已经做了三口径截断检验**。按加购日拆开，一小时内成交率 1.45~1.84%（平）、一天内 3.98~4.67%（平），只有"窗口内成交率"从 7.85% 单调掉到 1.63%——**短口径平、长口径掉，说明掉的是窗口不是业务**。所以干净参照是 11-25 批次的 7.85%。
- 被问 **"p 值这么小，你怎么还说类目不是关键？"** → 答：p 值回答的是"差异会不会是抽样偶然"，样本 61 万配对时这个答案永远是"不是"，所以 p 值必然极小、**没有信息量**。真正的证据是效应量 Cramér's V = 0.13（弱）和转化率 95% CI 中位宽度只有 0.72 个百分点（"显著"门槛低得没有决策价值）。**该不该按类目定 KPI，我用前后两半的复现性来判：Spearman 0.994、Top10 10/10。**

## 6. 后续规划：第二个项目（金融向）

**背景**：秋招互联网与金融两边都投，方向未定死。当前这个项目定位是**通用数据分析能力的证据**（漏斗 / 留存 / 转化 / 分层，是互联网电商的通用语言）。

**决策（2026-09-10 定）**：本项目**不换数据集**，做完当保底。等金融向投递真正铺开时，**另起一个规模更小的信贷分析项目**，与本项目互补：

| | 本项目（淘宝漏斗） | 后续项目（信贷，待启动） |
|---|---|---|
| 回答的问题 | 用户在哪一步流失 | 谁在什么条件下会违约 |
| 核心方法 | 漏斗 / 留存 / 分层 / 序列 | **vintage 账龄曲线** / 坏账分群 / 风险定价 |
| 对口方向 | 互联网 / 电商 | **银行 / 保险 / 风控** |
| 数据候选 | 淘宝 UserBehavior（已有） | Lending Club 信贷数据（有金额、字段丰富） |
| 规模 | 1000 万行 | 可小得多，够讲清 vintage 即可 |

**为什么这样排**：中国学生作品集里做信贷 vintage 的极少，是真正能拉开差距的角度；但它不是"电商数分"的通用语言，所以不能替代本项目。两个项目覆盖两个方向，比把宝押在一个上稳。**启动时机：本项目 P5 收尾之后，或金融岗投递集中开始时。**
